## Needs a user decision

1. **How `umas init` reaches Keycloak (rows 5, 24, 25, 27).**
   - (a) Run the kc-axi CLI as a subprocess with `--json`. Access-control 3.1 already names a subprocess, and item 12 lets the consumer choose. Consequence: row 1 (JSON contract) and created-id reporting (row 25) must be done first.
   - (b) Import the kc-axi Python package. Consequence: the embedded API (row 27) must be specified.
   - (c) UMAS calls the Keycloak REST API itself, as access-control 5.6 says today. Consequence: the no-secret, allow-list and idempotence rules are copied into UMAS.
   - Assessment: (a) keeps one code path for the no-secret and idempotence rules.
   - Recommendation: (a). Update access-control 5.6 and interfaces 5.9 and 7.

2. **Where a runtime client secret lives (row 4).**
   - (a) The kc-axi secrets file in the user configuration directory, read by the service process that owns the secret. It is owner-only and outside git. Consequence: no new command is needed. Generations and rollback (3.5) are kept. The reader must not run in a Worker sandbox (kc-axi 5.4, 9).
   - (b) An environment variable or an OS secret store, with a new kc-axi command to write the value there. Consequence: a new command, and rollback is lost unless it is added.
   - Assessment: (a) uses the mechanism kc-axi already has.
   - Recommendation: (a). Amend access-control "Service principal lifecycle" step 3.

3. **Confirmation for destructive commands (row 10).**
   - (a) `--yes` required for `down --purge`, `secrets rotate`, `secrets prune` and `disable-user`. `up` and plain `down` are unchanged.
   - (b) No `--yes` on these commands.
   - Assessment: `down --purge` deletes all Keycloak data. `libs/README.md` rule 6 requires a refusal by default on data-losing actions.
   - Recommendation: (a).

4. **Plan and apply output in full (row 7).**
   - (a) `plan` and `apply` print every action, whatever `--limit` says. Consequence: long output for a large realm.
   - (b) Keep the limit and compute `plan_hash` over the printed rows only. Consequence: `--expect` no longer covers the whole plan.
   - Recommendation: (a).

5. **Guards for users files and remote targets (rows 18, 19).**
   - (a) Refuse a users file inside a git work tree (exit 2, as for `secrets_path`). Require `--allow-remote` and `--yes` for any non-loopback `apply`, config or users.
   - (b) Warn only.
   - Recommendation: (a).

6. **AXI conformance and libs open points 1 and 2 (rows 20, 26, 29, 40).**
   - (a) Conform fully: a no-argument view, `bin:` and `description:`, default limit 20, TOON encoding, exit 1 for `plan`. Consequence: a second renderer, and scripts that branch on 8 break.
   - (b) Keep the deviations, record each in section 10 with its reason, and add kc-axi to the fit table. Keep 8 for `plan` so "drift" differs from failure.
   - Assessment: (b) is cheaper and keeps the plan exit code that scripts need. An agent-called tool still needs a no-argument view (rule 7).
   - Recommendation: (b), plus the no-argument view.
